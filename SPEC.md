# mx44

block-based DSP module: a simple **4×4 matrix mixer** with a per-output
**base-width** bandpass (1-pole HP then 1-pole LP, 6 dB/oct each) in the
elektron sense: `base` sets the HP corner and `width` sets the distance
from there up to the LP corner. fully open (`base` min, `width` max) is
**transparent**, so the filter is always in circuit and there is no
dry/wet control.

four ADC inputs feed four internal input buses; each input bus is sent to
four output mix buses through independent matrix levels; each output mix
bus passes through its bandpass, then drives one DAC through an output
level. four panel CV DAC outs (`cv1`…`cv4`) are independent of the audio
matrix, each with its own slew. every amplitude / CV control has 1-pole
slewing (`filter_1p_lo_blk` in `dsp_block`). slews advance **once per
audio block** (`MODULE_BLOCKSIZE` frames); bees still send per-sample
integrator coeffs, converted with `c → c^N` so convergence time stays
equivalent. matrix send slews share one time constant per **input** (all
four sends from that input use the same slew). filter cutoffs use a fixed
internal slew (not exposed).

parameter labels are **1-based** (`in1`…`in4`, `out1`…`out4`, `cv1`…`cv4`).
ADC/DAC/CV hardware channels remain 0-based (`adc0`…`adc3`, `dac0`…`dac3`,
`cv_set(0..3)`); `in1` / `out1` / `cv1` map to channel 0, `in4` / `out4` /
`cv4` to channel 3.

## topology

```text
adc0 ──►[in1]──┬──[in1-1]──►┬──[bpf1]──────►[out1]──► dac0
               ├──[in1-2]──►┤
               ├──[in1-3]──►┤
               └──[in1-4]──►┤
                            │
adc1 ──►[in2]──┬──[in2-1]──►┤
               ├──[in2-2]──►┤
               ├──[in2-3]──►┤
               └──[in2-4]──►┤
                            │
adc2 ──►[in3]──┬──[in3-1]──►┤
               ├──[in3-2]──►┤
               ├──[in3-3]──►┤
               └──[in3-4]──►┤
                            │
adc3 ──►[in4]──┬──[in4-1]──►┤
               ├──[in4-2]──►┤
               ├──[in4-3]──►┤
               └──[in4-4]──►┘
                            │
                         (sum per
                          out bus)
```

each amplitude `[…]` box has slew. `[bpfY]` is a 6 dB/oct base-width
bandpass:

```text
for each input X in 1..4:
  inX          — level into the input bus (slew: inXSlew)
  inX-1..inX-4 — sends into out1..out4 mixes (shared slew: inXMixSlew)
for each output Y in 1..4:
  outYBase     — HP corner, in semitones above 1 Hz (0 = HP open)
  outYWidth    — distance up to the LP corner, in semitones (max = LP open)
  outY         — level from filtered mix bus Y to dac(Y-1) (slew: outYSlew)
for each CV channel N in 1..4:
  cvN          — panel CV DAC level 0…10 V as fract32 (slew: cvSlewN)
```

CV is flushed once per block via `cv_set` + `cv_commit` (see
`bfin_lib_block/SPEC_CV.md`).

signal equation (per sample / frame inside the block), after slewed gains
have been **prepared once for the block**. arrays below are **0-based**
hardware indices; param `in(k+1)` / `out(k+1)` control index `k`:

```text
bus_in[k]  = adc[k] * in[k+1]
mix[m]     = Σ_k  bus_in[k] * in[k+1]-(m+1)
hpSt[m]    = out(m+1)Base                  (slewed)
lpSt[m]    = hpSt[m] + out(m+1)Width       (clamped to the table's open end)
hpA[m]     = filter_bp_alpha_hp(hpSt[m])   # once/block
lpA[m]     = filter_bp_alpha_lp(lpSt[m])   # once/block
filt[m]    = LP(HP(mix[m]))                # 1-pole each, stored alphas
dac[m]     = filt[m] * out[m+1]
```

coefficients come from `dsp_block/filter_bp_alpha_tab.h`: two semitone-
indexed `fract32` tables (generated by
`utils/param_scaling/gen_bp_alpha_tab.py`), read once per block per output
with linear interpolation on the fix16 fraction. there are **no divides**
and no transcendentals in the module.

the HP coefficients are solved against the realized digital response, so
the −3 dB corner lands on the nominal frequency across the whole base
range; the analog-prototype formula they replace drifted to 1.8× by 5 kHz
and past Nyquist by 10 kHz. the LP uses `1 − e^(−ωT)`, which is exact to
about 2 kHz and keeps climbing monotonically toward unity above Nyquist so
the open end is transparent rather than −3 dB down.

overflow: use saturating / guarded accumulation consistent with other
`modules_block` mixers (e.g. spray / mix-style `add_fr1x32`). the HP body
in `filter_bp_blk` evaluates at half scale, because `in - lastIn` reaches
1.93× full scale near Nyquist and would otherwise saturate (26 % THD on a
0 dBFS 20 kHz tone).

## parameter summary

| group | count | labels | type (bees) |
|-------|------:|--------|-------------|
| input levels | 4 | `in1`…`in4` | amp |
| input level slews | 4 | `in1Slew`…`in4Slew` | integrator |
| matrix sends | 16 | `inX-Y` (X,Y ∈ 1…4) | amp |
| matrix send slews | 4 | `in1MixSlew`…`in4MixSlew` | integrator |
| output (per out Y) | 4×4 | `outY`, `outYSlew`, `outYBase`, `outYWidth` | amp / integrator / fix / fix |
| CV levels | 4 | `cv1`…`cv4` | fix |
| CV slews | 4 | `cvSlew1`…`cvSlew4` | integrator |
| **total** | **52** | | |

amp params: `0`…`PARAM_AMP_MAX` (`0x7fffffff`), displayed as dB in bees.
integrator (slew) params: `0`…`PARAM_SLEW_MAX`, displayed as seconds-to-
convergence; default around `PARAM_SLEW_DEFAULT` (`0x7ffecccc`) matching
mix/spray.

filter base / width: `eParamTypeFix`, **radix 10**, fix16 **semitones
above a 1 Hz root** (`f = 2^(st/12)` Hz, so every 12 semitones is a
doubling and `st = 12n` is exactly `2^n` Hz). base range `0`…`156`
(1 Hz…8192 Hz); width range `0`…`192`. the LP corner is `base + width`
semitones, clamped to the open end of the table.

the log axis is what makes this an elektron-style base-width filter: a
fixed `width` keeps the band a constant number of octaves wide as `base`
sweeps. it also gives between's linear fix scaler a sensible feel —
radix 10 steps **0.5 semitone** per fine detent and **4 semitones** per
coarse tick, about 48 coarse ticks end to end, while still displaying the
value in semitones.

defaults `base = 0`, `width = 192` put both stages at their identity
coefficients, which measures **±0.0000 dB** across the band, so the module
still boots as a plain matrix mixer.

landmark values:

| semitones | Hz | | semitones | Hz |
|----------:|-----:|--|----------:|------:|
| 60 | 32 | | 132 | 2048 |
| 84 | 128 | | 144 | 4096 |
| 108 | 512 | | 156 | 8192 |
| 120 | 1024 | | 192 | 65536 (open) |

CV levels: `eParamTypeFix`, `0`…`PARAM_CV_MAX` (`0x7fffffff` = 10 V), radix
16. default `0`. each has `cvSlewN` (integrator, default
`PARAM_SLEW_DEFAULT`).

suggested startup: identity matrix (`inX-X` = unity, other sends = 0),
`in*` / `out*` = unity, `in*Slew` / `out*Slew` = min (`0`), matrix send
slews = `PARAM_SLEW_DEFAULT`, `out*Base` = 0, `out*Width` = 192, `cv*` =
0, `cvSlew*` = `PARAM_SLEW_DEFAULT`.

## implementation notes (block DSP)

- live under `modules_block/mx44/` with `bfin_lib_block` and
  `module_process_block`.
- slewing: one `filter_1p_lo` (or equivalent) per amplitude target; for
  matrix sends, four filters per input share the same `inXMixSlew`
  coefficient.
- output filters: `dsp_block` `filter_bp_blk` (HP then LP); cutoff params
  stored as fix16 semitones and slewed with a fixed internal
  `filter_1p_lo` rate, then converted to coefficients through
  `filter_bp_alpha_tab`. slewing on the log axis makes cutoff sweeps sound
  even.
- `mx44_params.h` deliberately does **not** include `filter_bp_alpha_tab.h`
  — it is also compiled by host `gcc` for the descriptor, where
  `fract_math.h` is unavailable. the semitone limits are duplicated as
  `PARAM_BASE_ST_MAX` / `PARAM_WIDTH_ST_MAX` and checked against the table
  header by a compile-time assert in `mx44_module.c`.
- param labels must fit `PARAM_LABEL_LEN` (16); names above are ≤11 chars.
- CV outs use `bfin_lib_block` `cv_set` / `cv_commit` once per block after
  audio; `cv1`→hw ch 0 … `cv4`→hw ch 3.
- keep enum order stable once published; bees / between / ctl apps key off
  indices and labels. output params are grouped **per output** (level, slew,
  base, width). CV params are appended after outs so earlier audio indices
  stay stable.
- **0.9.0 breaks presets.** `outYWet` / `outYWetSlew` are gone, and
  `outYBase` / `outYWidth` changed from Hz to semitones. between resolves
  presets by label and ignores unknown ones, so the two dropped params load
  harmlessly, but any stored base / width is now read as semitones —
  re-dial and re-save filter settings. redeploy the `.dsc` with the `.ldr`.

### suggested enum grouping

```text
in1..in4
in1Slew..in4Slew
in1-1..in1-4, in1MixSlew
in2-1..in2-4, in2MixSlew
in3-1..in3-4, in3MixSlew
in4-1..in4-4, in4MixSlew
out1, out1Slew, out1Base, out1Width
out2, out2Slew, out2Base, out2Width
out3, out3Slew, out3Base, out3Width
out4, out4Slew, out4Base, out4Width
cv1..cv4
cvSlew1..cvSlew4
```

(exact C enum names can use underscores, e.g. `eParam_in1_2` for label
`in1-2`.)
